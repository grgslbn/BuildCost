Entry Points

🏠
Estimation
POST /api/estimate-process
End-to-end pipeline for a single building plan uploaded via the public landing page or customer portal. Produces the full cost report shown to the user.
300s max No auth (internal)
📁
Reference Dossier
POST /api/process-dossier
Processes an expert reference file — full page classification, metadata extraction, SQM + QQP extraction, expert-F back-calculation, and self-learning triggers.
300s max Auth required
📊
Benchmark
/api/benchmark/run/…
Orchestrates estimation on every reference dossier in sequence. Creates estimation rows, fires the estimate-process pipeline per dossier, polls for results, then records error metrics.
Sequential Auth required
🔍
Quick Scan
POST /api/analyze-pdf
Lightweight scan: splits pages, classifies each page type, extracts metadata from expert-report / pricing-table pages. Returns JSON — no SQM, no cost, nothing stored to DB.
300s max Auth required

Flow Deep-Dives

🏠 estimate-process — Full Pipeline

Main user-facing pipeline. Triggered by /api/estimate as fire-and-forget. Internal 250s watchdog before Vercel's 300s hard limit.

  • 1
    Load settings & download PDF
    Reads extraction model, QQP model, pricing tiers, ABEX, and versioned prompts from DB. Downloads from Storage.
    estimations ← status='processing'
  • 2
    Local floor-plan detection
    mupdf keyword heuristics scan page labels/content for "plan", "ground floor", "etage", etc. Zero API cost. Returns floor plan page numbers + labels.
    local only — no API
  • 3
    Render selected pages → PNG
    mupdf + sharp at 300 DPI, max 5000px. Landscape detection: splits double-plan sheets into 2 or 3 sub-images. Fallback: base64 PDF blocks if mupdf unavailable.
    mupdf + sharp
  • 4
    SQM Extraction
    Claude Sonnet with extended thinking (10k budget). Streams response. Max 12 floor-plan pages. Extracts rooms, areas per category, building type, scale confidence. Retry once with T=0 on JSON failure.
    Claude API — 26,384 max tokens — Thinking ON api_call_log ← tokens in/out
  • 5
    QQP Extraction
    Claude Sonnet without thinking. 8,192 max tokens. Sends SQM output + plan images. Extracts 35+ quality parameters with scores [0.0–1.0] and per-QQP confidence + reasoning.
    Claude API — 8,192 max tokens — Thinking OFF api_call_log ← tokens in/out
  • 6
    F prediction → Cost calculation
    Ridge regression model (from qqp_model_versions) maps QQP scores → F ∈ [0.70, 1.50]. Postcode lookup → regional factor. ABEX index lookup. Interpolate CAT1/2/3 prices, compute totals.
    pure maths — no API
  • 7
    Write result
    Full estimation data including SQM breakdown, QQP values, cost breakdown per category, confidence scores, processing time.
    estimations ← status='complete'

📁 process-dossier — Reference Analysis

Richer flow for training data. Includes AI page classification, metadata extraction, expert F back-calculation, and self-learning triggers.

  • 1
    Load dossier & download PDF
    Loads reference_dossiers row. Downloads PDF from Storage.
  • 2
    Split all pages
    splitPdfPages() — base64 single-page PDFs. Used for both classification and rendering.
  • 3
    Page classification (AI)
    Claude Sonnet, batches of 4, 512 tokens per batch. Types: floor_plan / expert_report / pricing_table / photo / cover / other. Stored once; reused on re-runs.
    Claude API — 512 tokens/batch — Thinking OFF reference_dossiers ← page_classifications api_call_log
  • 4
    Metadata extraction
    Filters to expert_report + pricing_table pages (max 6). Extracts address, postcode, building type, apartment count, known price, known SQM, expert finishing level.
    Claude API — 2,048 tokens — Thinking OFF reference_dossiers ← address, postcode, …
  • 5
    Render floor plans → SQM Extraction
    Same as Estimate flow: mupdf tier-1 then base64 fallback. Claude Sonnet + 10k thinking. Stream + retry logic.
    Claude API — 26,384 max tokens — Thinking ON reference_dossiers ← sqm_extraction
  • 6
    QQP Extraction (text-only)
    No plan images — prompt uses SQM output + known expert context (price, notes). Extracts same 35+ parameters.
    Claude API — 8,192 tokens — Thinking OFF dossier_qqp_values ← upsert per QQP
  • 7
    Expert F back-calculation
    If known_total_price and known_total_sqm available: reverse-solve F from cost formula + regional + ABEX factors. Clamp to [0.70, 1.50].
    pure maths — no API
  • 8
    Self-learning triggers
    If |prediction_error| > 15%: log suggested new QQPs to discovery log. Check if enough data to auto-calibrate Ridge model. Both non-fatal.
    qqp_discovery_log reference_dossiers ← prediction_error, status='analyzed'

📊 Benchmark — Accuracy Evaluation

Orchestrator that reuses the estimate-process pipeline across all reference dossiers and compares predicted costs vs. expert ground truth.

  • 1
    Create run
    POST /api/benchmark/run — selects dossiers (mode: "all" or "difficult"), creates evaluation_runs row, returns dossier list to client-side runner.
    evaluation_runs ← status='running'
  • 2
    Init estimation per dossier
    POST /api/benchmark/run/[runId]/init — creates estimations row with dossier's plan path and postcode.
    estimations ← status='uploading'
  • 3
    Fire estimation pipeline
    Client calls /api/estimate-process with estimationId. Full 7-step pipeline runs (steps 1–7 from Estimate flow above).
    ← estimate-process pipeline
  • 4
    Poll for completion
    Client polls /api/benchmark/poll-estimation/[id] every few seconds. Stuck detection: if updated_at hasn't moved in 6 min → marks as Vercel-killed.
  • 5
    Record result
    POST /api/benchmark/run/[runId]/record — computes CAT1/2/3 area error %, cost error %, F delta vs. expert ground truth.
    evaluation_results ← all error metrics
  • 6
    Finalize
    POST /api/benchmark/run/[runId]/finalize — aggregates: cost MAE, median error, % within 10%/15%, F MAE.
    evaluation_runs ← aggregate_metrics, status='complete'

🔍 analyze-pdf — Quick Scan

Lightweight inspection tool. No SQM/QQP, nothing stored to DB. Returns raw classification + metadata as JSON.

  • 1
    Download PDF from Storage
    Reads storagePath from request body. Uses admin client (service role).
  • 2
    Split pages (up to 40)
    splitPdfPages(buffer, 40) — produces array of base64 single-page PDFs.
  • 3
    Classify all pages
    classifyPages() — batches of 4, Claude Sonnet, 512 tokens/batch. Returns type, confidence, description per page.
    Claude API — 512 tokens/batch — Thinking OFF
  • 4
    Extract metadata
    extractMetadata() — filters to expert_report + pricing_table pages (max 6, fallback first 4). Extracts address, postcode, price, sqm, etc.
    Claude API — 2,048 tokens — Thinking OFF
  • 5
    Return JSON (nothing stored)
    Response: totalPageCount, processedPageCount, classifications[], floorPlanPages[], extractedMetadata. No DB writes.
    response only

Known Limitations & Failure Modes

⏱ Vercel 300s hard limit
SQM extraction with 10k thinking + QQP on a large VerzamelPDF dossier (20+ floor plan pages) typically takes 4–8 minutes — exceeding Vercel Pro's limit. Only ~5% of complex dossiers complete within the limit.
Internal 250s watchdog exits gracefully before Vercel kills the process. Benchmark stuck-detection marks estimations >6 min as failed.
🖥️ mupdf runtime availability
The high-quality PNG rendering (300 DPI, landscape splitting) depends on mupdf being available in the serverless environment. Not guaranteed on all Vercel runtimes.
Automatic two-tier fallback: if mupdf fails, sends raw base64 PDF document blocks to Claude instead. Lower quality but functional.
📄 Max 12 floor-plan pages
SQM extraction caps at 12 rendered floor-plan pages (MAX_SQM_PAGES). Large apartment buildings with many floor types may have plans beyond this limit silently ignored.
Local heuristic classification pre-filters to actual floor plan pages before the cap applies, mitigating impact for most files.
🔢 JSON parsing failures
Claude occasionally outputs malformed JSON, especially in SQM extraction for complex buildings. Single retry with temperature=0 and stricter prompt is built in, but if both attempts fail, the estimation errors out.
Retry with T=0 + stricter prompt resolves ~80% of failures. If both fail, estimation is marked status='error' with the raw message stored.
🗺️ Missing postcode → Regional factor = 1.0
If the extracted postcode isn't in the postcode_prices table, the regional factor defaults to 1.0 (neutral). This can skew costs significantly for rural or uncommon postcodes.
Postcode is extracted from the plan itself by Claude. If missing or unrecognised, the cost is still computed — just without regional adjustment.
👁️ Scale & small text legibility
Claude Vision struggles with very small dimension annotations or hand-written area labels on scanned/low-resolution plans. Scale_confidence below 0.6 flags an unreliable extraction.
Confidence scores propagate to overall_confidence. High-DPI mupdf rendering (300 DPI) mitigates most cases, but scanned plans remain difficult.
🧪 Ridge model accuracy
F coefficient prediction depends on the quality of training data (reference dossiers). With only 43 dossiers, the model may overfit or underfit for unusual building types.
Self-learning: if prediction error >15%, new QQP suggestions are logged. Auto-calibration re-trains the Ridge model when enough new data accumulates.
🌙 Browser tab sleep kills benchmark
The benchmark runner is client-side (for-loop in the browser). If Chrome throttles the background tab, the sequential loop stalls mid-run — dossiers already initiated may timeout without being polled.
Keep the benchmark tab in the foreground. Stuck detection automatically marks estimations that haven't updated in 6 minutes as failed.
🔄 QQP extraction: text-only for dossiers
The dossier flow sends no plan images to the QQP extraction step — it works purely from the SQM JSON output. This limits QQP quality for visual cues (window quality, facade materials) that aren't captured in area data.
Expert context (known_price_per_sqm, expert notes) is injected into the prompt when available, partially compensating for the lack of visual input.
