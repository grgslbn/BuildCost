Upload Processing — Old vs New

PlanBase · Pipeline Architecture · May 24, 2026

⚠ Old — Vercel direct (USE_QUEUE=false) ✓ New — Railway queue (USE_QUEUE=true) ↔ Shared — runEstimationPipeline()
USE_QUEUE
One env var, set on Vercel, determines the entire execution path.
false (default) → pipeline runs inline inside the Vercel function — hard 300s timeout. true → job is inserted into processing_queue, Railway worker picks it up — no timeout.
⚠ Rollback in 30s: set USE_QUEUE=false on Vercel → redeploy.

claim_queue_job() SQL
Atomic UPDATE with row-level lock — prevents two worker slots from claiming the same job simultaneously.
UPDATE processing_queue
SET status = 'claimed',
    worker_id = p_worker_id,
    started_at = now()
WHERE id = (
  SELECT id FROM processing_queue
  WHERE status = 'pending'
    AND job_type = ANY(p_job_types)
  ORDER BY priority ASC, created_at ASC
  LIMIT 1
  FOR UPDATE SKIP LOCKED
)
RETURNING *;

Limitations & Things to Watch
⚠️Worker Not Yet Deployed
Current state: USE_QUEUE=false (old path active). Railway worker exists in worker/ dir but hasn't been deployed yet. Migration 20260524_processing_queue.sql also not yet applied to Supabase.

Next steps: apply migration → deploy worker to Railway → set USE_QUEUE=true.
🔄2s Poll Latency
Worker polls Supabase every 2 seconds. After job insertion, there's a 0–2s lag before it's claimed. For customer-facing estimates this is negligible — user sees "Processing…" state. For benchmarks, this latency accumulates across many jobs (43 dossiers × avg 2s = ~90s extra).
💥Worker Crash Mid-Job
If Railway container crashes while a job is claimed/processing, the job stays in that state forever — no auto-timeout recovery today. The estimation row will be stuck in extracting_sqm or analyzing_qqp.

Workaround: manual reset in Supabase or re-submit. Future fix: a cron job that resets jobs stuck in claimed >15 min.
📸mupdf Render Fallback
mupdf renders PNGs at 300 DPI (landscape pages split in half). If mupdf fails, falls back to base64 PDF document blocks sent directly to Claude. Fallback is slower and less accurate — Claude reads native PDF instead of high-res rendered images. Watch logs for "mupdf render failed".
🧠SQM Extended Thinking — 10K Budget
thinking.budget_tokens = 10000 + max_tokens 26384. Extended thinking is the slowest part — typically 60–120s alone for complex plans. Retry (JSON parse fail) sends a second call without thinking at temperature 0. Two retries in a row would be ~200s just for SQM.
🗺️Postcode Fallback = Regional Factor 1.0
If Claude fails to extract a valid postcode from the plan, or the postcode isn't in postcode_prices, regional factor defaults to 1.0 (Brussels reference). This silently makes estimates less accurate for non-Brussels properties. Watch postcode field in estimations rows.
🔑Worker Env Vars Required
Railway container needs: SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, ANTHROPIC_API_KEY. Optional: WORKER_ESTIMATE_SLOTS (default 1), WORKER_BACKGROUND_SLOTS (default 2). Without service role key, worker cannot bypass RLS on processing_queue.
🔁Retry Logic — max_attempts=2
Failed jobs (exception thrown) increment attempts. If attempts < max_attempts (default 2), job resets to pending for retry. After 2 failures, status = error. Estimation row is also updated with status=error + error_message so the frontend shows it.
